# ADR-140: Bound terminal-run review recovery by consumer lifetime (amends ADR-091)

**Status: accepted (ratified 2026-11-05).**

## Context

#4861 proposes recovery for review work whose run has already settled. ADR-091 D2 enumerates the shared boot/restart-blocker eligibility predicate and its refusal slugs; its state-based scan can omit a review started during terminal-run reporting. A proposed `run_terminal` result and terminal-run scan change those decisions. Held-commit recovery can also lose a required supplemental review. The Captain requested an ADR amendment before #4861 proceeds.

This proposal covers terminal-run discovery, consumer eligibility, the associated restart guard, interrupted gating uploads and required-review retention. It creates no additional same-head bypass and does not authorize a reload during live runner work.

## Options

- A. Keep the current state scan and predicate. Terminal-run rounds may remain undiscovered.
- B. Add bounded terminal-run discovery and distinguish rounds with a live verdict consumer from rounds without one, using the same consumer rule in boot recovery and restart blockers.
- C. Re-dispatch every terminal-run round. This spends reviewer budget even when no consumer can use the result and cannot safely replace a dead synchronous gating request.

## Recommendation

Option B.

## Decision

**Accepted 2026-11-05** by the Captain (manual ratification path; approver, exact body and erratum hashes in the ratification comment). Adopt Option B and D1-D9. This amends ADR-091 D1, D2 and D8 and records the interrupted-upload contract only as stated below; ADR-095's review-coverage hold, operator-rerun eligibility and separate marker remain unchanged.

D1. A shared consumer predicate classifies cancelled runs as having no remaining review consumer. A succeeded decomposition child also has no consumer while its parent is terminal, and a failed parent is terminal (case succeeded_child_of_failed_parent). A failed parent can be revived; a round closed meanwhile is not an approval, the coverage hold still applies, and the slice may need later recovery after revival. Failed runs retain the existing round/stage eligibility checks because they can be revived; they are never classified no-consumer merely for being failed. Other succeeded runs, including children whose parent remains active, also retain those checks. A missing or unreadable run or required parent is an unknown result, never proof that no consumer exists.

D2. Before authority/backend/depth refusals can obscure the no-consumer case, the shared predicate returns `run_terminal` for a proven no-consumer round. Boot recovery closes such an orphan with the existing synthesize-failed mechanism and the named reason, rather than re-dispatching it. Restart blockers omit that proven no-consumer round. Gating rounds with a consumer retain their existing closure and blocking behavior. Other ADR-091 eligibility requirements and dedup-marker restrictions remain intact.

D3. In addition to the existing state scan, boot recovery discovers terminal-run review starts within a bounded 24-hour lookback. Restart-blocker discovery uses each round's own configured-reviewer budget within a 24-hour discovery lookback; rounds whose configured budget exceeds that lookback are an explicit residual. Within the discovery window, an unrelated qualifying round must never admit an expired round as a blocker. Discovery retains run, stage and round identity through evaluation. A pending boot handoff remains visible under the existing handoff guard.

D4. The initial query cap is 500 newest audit rows per review kind per scan, with memoized run reads. Reaching a cap must report truncation accurately; the implementation may not imply complete coverage. Historical rounds outside boot lookback remain a stated residual. Scan cost, caps and degradation are documented and pinned against real store ordering.

D5. User-visible discovery preserves the route's existing account and repository visibility. Audit discovery is candidate discovery only. A run-specific result may be emitted only after the same run visibility checks that apply to the state scan succeed. If a candidate cannot be loaded or visibility cannot be established, return a generic fail-closed unavailable response carrying no candidate identifiers or internal error text. A NULL-account audit row is never sufficient evidence of run visibility. Boot's internal error reporting remains separate from user-visible output. The existing anonymous ListRuns visibility posture remains: an anonymous caller with no account filter can see candidates that posture admits across accounts. Adding terminal-run discovery enlarges that visible set to qualifying terminal rounds inside the lookback, without adding fields. This historical visibility cost must be stated in endpoint documentation and PR Notes.

D6. Parent gate projections may describe lost child rounds, but advertise a recovery action only when the existing action's eligibility and required recorded input availability are verified for that round. A configured trace store alone does not establish that its recorded bundle exists and can be decoded. Missing or malformed required inputs do not get an advertised rerun action. An interrupted gating round must not be offered the advisory-only rerun verb. No new gating-recovery verb or authority is decided here. Unknown eligibility must be stated without a speculative action; the coverage hold remains in force.

D7. The generic HTTP 503 from unknown restart-blocker visibility must refuse reload and post-merge before teardown, and count as not quiet for --when-quiet. The existing explicit --force override remains, with a terminal warning. Forcing an undecidable 503 can orphan live work and leaves no durable override record. Existing behavior for other degraded statuses and transport failures is outside this amendment (#5054); no authentication or caching change is introduced to the existing anonymous route. One unreadable foreign candidate may therefore temporarily refuse reload for all callers, without disclosing candidate identifiers. Repeated-read capacity and shared availability (#5057, #5058) are accepted residuals of this bounded change; the public endpoint is not thereby load-hardened.

D8. Record the Captain's separately permitted interrupted gating-upload contract: a review stopped by daemon shutdown is an explicit interrupted outcome, emits no fabricated terminal verdict and does not advance the stage or run post-loop settlement. The three signed plan, trace and supplemental pull-request upload routes answer HTTP 503 review_round_interrupted while interruption is current. A byte-identical upload after a lost gating round on the next process answers HTTP 409 without advancing; a closing current process must likewise never advance over its stopped round. This creates no same-head gating bypass and authorizes no gating re-dispatch.

A retry of a supplemental gating upload while its original pass is proven live in this process answers retryable HTTP 503 review_round_in_flight and never advances from the duplicate request. Process-local ownership must cover the artifact-visibility-to-pass-completion interval for the current attempt, release on every exit, and distinguish a live pass from a previously lost one without relying on partial verdict counts alone. Ownership has a finite lifetime: the configured reviewer count times the larger of the deployment review budget ceiling and the stage's review timeout, plus a fixed non-review allowance, and shutdown cancels it. A dependency that honours its context therefore cannot hold ownership past that bound. Caller disconnect does not revoke it. A stopped closing-process round retains 503 review_round_interrupted; a lost prior-process round retains 409 without advancing.

A gating supplemental pass durably records its start, audit category `supplemental_review_started` with stage_attempt, head_sha, configured_agents and required_paths, before it invokes any reviewer, and each verdict records in `stage_attempt` the attempt that invoked it, captured before invocation. A recorded start on the current attempt with an incomplete verdict set is a lost pass: it answers as above and never dispatches again on that attempt. A new attempt gets one start. A verdict from another attempt never settles the current attempt, whatever its append time; a recorded reject at that head still binds. A failure to read or write this evidence invokes no reviewer and advances nothing. A legacy verdict with no recorded attempt is unknown and settles nothing on a stage with an attempt anchor.

The existing stage-retry recovery remains: a stage retry's resumed upload that carries a recorded required review obligation re-enters the existing required gating path once on the new attempt. That is not a same-attempt re-dispatch. Verdicts from an earlier attempt and partial passes never settle it, and a recorded reject at that head never advances.

Long passes continue rather than loop. The review_round_in_flight response carries `Retry-After` in delay seconds and `X-Fishhawk-Review-Pass-Remaining-Seconds`, the seconds left on the owner's lifetime. The runner's pull-request upload treats only that exact response as proof of a live pass: it re-posts the same signed bytes after Retry-After within a request-local bound fixed at the first such response, remaining plus a 30-second settle allowance. A later response cannot extend the bound, a live response resets the ordinary blip retry budget, an absent or out-of-range remaining value (outside 1 second to 24 hours) stays an ordinary 5xx, any other answer decides, and the caller's earlier cancellation wins. Exhaustion fails the stage retryably and moves nothing. This continuation never reads, arms, spends or resets the shared terminal-egress phase or ADR-141 D4's push-report budgets. A runner predating it keeps the ordinary blip budget and can exhaust while a pass is live, which fails closed. This is not an unlimited wait guarantee.

The two normal started-row restart scans cover plan_review_started and implement_review_started; they do not discover supplemental_review_started. D6 and D8 therefore do not by themselves expose a live supplemental pass through those scans: a reload can interrupt it, after which the required obligation survives and the upload refuses rather than advances. The visibility follow-up is #5077. A bounded reviewer cancellation clock may run during HTTP drain so process-group cancellation completes before the operator's daemon kill grace.

D9. A required supplemental review obligation known when a held-commit checkpoint or scope-completeness park is recorded is durable recovery state. Its wire form is `review_obligation` {head_sha, stage_attempt, supplemental_scope_exemptions}: an absent or null list is unknown, an empty list is known none and a non-empty list is known required. It survives the failure report, the durable record, the prompt projection, the runner decode, the resumed upload and repeated failed resumes, bound to the recorded head. A known-required report is stored under audit category `review_obligation_checkpoint`, and its pull_request_failed sibling carries no push_checkpoint, so a reverted backend re-runs the agent. Capability token `review-obligation-resume` runs runner to backend; `supports_review_obligation_resume` and `held_commit_review_obligation` run backend to runner. The resume offer is read only from the stage's newest carrier, so a newer row withholds the offer and the retry is a full agent pass; withholding an offer discharges nothing.

Discharge. Recording or opening a pull request, a newer artifact and any other row are never evidence that required review completed. At a recorded head on the current stage attempt, the only proof is a `supplemental_review_started` row for that attempt and head, at least its configured_agents `implement_reviewed` rows with origin base_rebase_reinvoke, that head and that `stage_attempt`, and no reject at that head from any attempt. It is derived on read from rows the pass owner writes; no new row is added. Until it exists, an upload at that head missing a recorded path answers HTTP 409 review_obligation_missing and creates no artifact, whether the pass is live or lost; a read error answers 500 and changes nothing. The obligation source is the newest of review_obligation_checkpoint, scope_completeness_parked and supplemental_review_started at that head. With the proof, an omitting upload still takes the pass's ownership, so it answers 503 review_round_in_flight until the owner has applied its edge and cannot apply a second one. A different head is a different tree with its own review and lineage checks.

Unknown state. A standalone pr_open, push or exempt-park carrier with no recorded obligation, on a stage whose configured implement review is gating or unreadable, is declined at the prompt with reason `review_obligation_unknown` and a verified_tree_discarded row; the retry is one full agent pass. A non-gating or no-pass configuration resumes as today. A reverify or decomposition-child carrier proves none by construction, and a recorded empty obligation proves none. A non-empty obligation served to a runner lacking the capability is totally declined with reason `runner_review_obligation_capability_absent`. Against a backend lacking the capability, the runner records no resumable state for a non-empty set and does not read that backend's held-resume fields as proof of none.

Park. A park reporting a non-empty obligation omits base_sha from the park row and the parked audit payload, and a valid obligation keeps the true value only in payload key `required_review_base_sha`. An older resolver takes its existing no-base fail-closed branch on exempt, so that retry is one ordinary agent pass; the current resolver resumes the held commit with the obligation. Head, branch, verified tree, shortfall and PR text are unchanged, no field holds a false value, and a build-required park and the red-tree guard are untouched. Parks with no obligation key or a known-empty one stay resumable as today.

Runner skew. A backend that does not advertise the capability, or sends no obligation list, proves nothing: for a standalone pr_open, push or exempt resume the runner runs the ordinary agent pass in the same dispatch. Reverify and child kinds proceed. Cost: one agent pass per such resume during that skew, non-gating configurations included, because the runner cannot read review configuration.

Named residuals, not claimed safe: a reverted backend still serves a carrier with no recorded obligation (an older runner's report or a pre-change row) as it does today, and it ignores the missing-obligation refusal and the attempt evidence. Reverted software is never assumed to obey a new field. The rollback evidence is component-seam evidence, not a whole-stack proof. Known-none remains runner-attested under the ordinary upload path's existing trust boundary. Resume capability advertisement is advisory; it is not proof that a reporting client implements the contract honestly. The server-side missing-obligation refusal protects the recorded obligation and does not defend against a compromised runner fabricating known-none. Server-derived or cross-checked evidence is follow-up #5078.

## Consequences

Terminal-run review work is discovered within explicit bounds. A reload no longer waits for a verdict with no possible consumer; rounds with a consumer retain fail-closed treatment. The terminal scan adds bounded audit/run reads to the current route; load and cap behavior require implementation evidence. Unknown visibility can make the whole restart-blocker request unavailable, preserving confidentiality at the cost of a temporary reload refusal. Required review survives recovery at the cost of one agent pass per unknown carrier or withheld-base park across a version boundary, and a runner can wait up to a pass's lifetime on a long supplemental pass.

### Validation

Behavioral evidence must cover failed/cancelled runs, a succeeded child with active versus terminal parent including a failed parent, gating and advisory authority, every earlier eligibility refusal, missing and unreadable parent/run, mixed round budgets, pending handoff, newest-first cap/truncation behavior, account/repository isolation including NULL-account candidates, truthful recovery actions, a same-head omitting upload while a required pass is live and after it is lost, a genuine discharge, and a live pass outlasting the ordinary retry window through approve, reject, loss, deadline, caller cancellation and a later terminal upload. Mutations must demonstrate detection of consumer-predicate bypass, per-round-window bypass, visibility bypass, the opened-row inference, a deleted completion-proof guard and a deleted live-pass continuation, without printing private candidate details.
