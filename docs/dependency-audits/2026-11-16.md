All eight Go modules were independently updated and tidied before workspace sync.
All reachable external module paths, including tests, use the latest version
reported for that path. Major-version migrations were checked separately: the
Anthropic SDK moved to v2, and YAML moved to the maintained v3 fork. Workspace
metadata also contains older dependencies used only by upstream packages that
Fishhawk does not import; these were inspected but not forced into direct pins.
The five internal pseudo-version references now point to the reviewed main SHA.

Both JavaScript lockfiles were freshly resolved and checked with a recursive
update. The inventory covers 602 unique npm registry names. Some resolved
packages remain below the registry's global latest because their parents require
an older major or pnpm's publication-age policy excludes the newest release.
Arbitrary transitive major overrides would bypass those compatibility contracts.
No resolved version was marked deprecated by the registry at review time.

pnpm 12 configuration now lives in each project's `pnpm-workspace.yaml`, including
the existing scoped minimatch security override and approved build scripts.
`pmOnFail: ignore` preserves a single-document lockfile, which GitHub's dependency
graph can read; `engines.pnpm` and CI still require the exact package-manager
version. The offline gate now carries public registry publication metadata as
well as package tarballs, so the normal supply-chain policies work without a
network connection. A regression test rejects multi-document lockfiles.

The Anthropic SDK upgrade explicitly preserves API version `2023-06-01`,
`x-api-key` authentication, empty-key behavior, and the exclusive OAuth bearer
path. SDK v2 suppresses ambient credential autoload when explicit credentials are
provided. Existing request/response, token-accounting and credential tests pass;
negative controls independently remove the API-version and authorization-header
compatibility options and demonstrate that the wire tests reject both changes.
No live provider or review-quality measurement is claimed by this update.

## Evidence

- Each of the eight modules passed standalone `go mod verify` and a readonly
  build with workspace resolution disabled.
- `govulncheck` 1.9.0 reported no vulnerabilities for all eight modules, with and
  without tests, on the host platform. Source scans including tests also passed
  for all eight modules targeting Linux AMD64 and ARM64. Both npm audits
  reported zero findings.
- Frontend formatting, lint, types, 825 tests and production build passed. The
  same checks passed in the candidate Linux ARM64 gate image with network access
  disabled and an arbitrary non-root UID. Clean CI-style frozen installs passed
  for both projects with normal lifecycle-script policy enabled.
- Site checks reported zero diagnostics; the production build generated 24 pages.
- Fifteen CI contract tests passed, including a negative control proving that a
  two-document pnpm lockfile fails the security-graph check. A separate negative
  control proves that a mismatched Go service image fails the image-pin check.
- Isolated container smoke tests exercised PostgreSQL 16.16, RustFS health and
  bucket operations with AWS CLI 2.40.3, and Jaeger UI plus OTLP ingestion/query.
  No shared stack restart or live database migration was performed.
- Terraform formatting and validation passed after backend-disabled initialization
  with AWS provider 6.73.0. No account plan/apply was performed.
- Dependabot schema validation, instruction-context checks and focused parser,
  provider-adapter, process-supervisor and gate-image tests passed. Review prompt
  evaluation reported no trigger; no prompt/persona/corpus was changed.

The first full host gate passed seven modules and failed backend on two Docker
container-inspection timeouts before migration assertions. The baseline passed
the two cases three times and the full migration package once; the updated
branch passed the complete migration package three times under race detection.
The focused comparisons did not reproduce the timeout. Startup contention is
tracked in [#5428](https://github.com/kuhlman-labs/fishhawk/issues/5428). The final
host gate uses `FISHHAWK_TEST_P=2 GOMAXPROCS=4`, with every gate still enabled.
Four shell TLS-proxy cases require port 8443 and were skipped because the shared
listener occupies it.

The PR test plan records the final full verification result and hosted CI state.
The candidate gate-image and service smoke tests above cover local ARM64; hosted
image builds establish the other release architectures.
